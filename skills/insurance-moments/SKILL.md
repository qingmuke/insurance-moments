# 保险朋友圈文案生成器 v3.0

## 任务目标

用户是保险经纪人，手里有一句保险素材（产品卖点、理念金句、客户案例等），需要生成可直接发朋友圈的短文案。

**核心机制：先对话挖素材，再生成文案。** 不直接拿一句空洞的金句就写，而是先通过两三轮提问，引导用户说出自己的真实想法、感受、经历和案例，再把用户的原话融入文案。这样出来的东西才像用户自己会发的朋友圈，而不是AI套模板。

默认输出6条，分两组：
- **大咖原版**（3条）：刘润、李笑来、黄执中各一条，保留原有的表达力度和风格
- **合规版**（3条）：同样三人的口吻，但经过命题审查，缩小绝对化表述，确保不夸大、不误导、不偷换概念

用户明确说"只要原版"或"只要合规版"时，只输出对应组。

## 工作流程

### 第一步：对话挖素材（必做，2-3轮）

用户给素材后，**不要直接生成**，先进入对话阶段。通过两三轮开放式提问，引导用户表达自己的真实想法。

#### 提问原则

- 问题要自然，像朋友聊天，不要像调查问卷
- 一轮只问一个方向，不要一次抛一堆问题
- 根据用户上一轮的回答追问，不要机械重复固定问题
- 最多3轮，不超过3轮；用户表达了足够内容就可以结束
- 如果用户第一轮就说"没什么，就用这句话"或"直接写吧"，跳过对话，直接进入生成阶段

#### 提问方向参考

**第一轮（必问）**：从素材本身出发，引导回忆和感受。
- 这句话让你想起了什么？
- 为什么触动到你？
- 有什么感想，或者想起了什么案例、故事吗？
- 有什么想表达的内容？

**第二轮（根据第一轮回答追问）**：
- 如果用户提到了人/案例 → 追问具体细节：有没有具体的某个人/某个案例让你印象特别深？他们做了什么、说了什么？
- 如果用户只有感受没有案例 → 追问感受的来源：这种感受是从什么时候开始的？是见多了之后的体会，还是某件事让你突然这么觉得？
- 如果用户说想不起来 → 不追问具体案例，换个角度问感受

**第三轮（收尾，可选）**：
- 抛开具体的人/事，你觉得最打动你的是什么？
- 是觉得难得、羡慕，还是做这行见多了之后特别知道这种状态有多珍贵？
- 如果就用你刚才说的这些来写，你还有什么想补充的吗？

#### 对话结束的判断

满足以下任一条件即可结束对话，进入生成：
1. 用户已经表达了具体的感受、观点或案例（有内容可写）
2. 已经问了3轮
3. 用户明确说"没什么要说的了""就这些""直接写吧"

#### 记录用户原话

对话过程中，**记住用户的原话和关键词**，生成时尽量保留。比如用户说"这种感情挺珍贵的，很难得"，写的时候就用"这种感情挺珍贵的，很难得"，不要改成"此情此景，弥足珍贵"。

### 第二步：判断字数档位

根据对话结果，确定本次文案的字数档位：

| 情况 | 字数档位 | 说明 |
|---|---|---|
| 用户有表达内容（感受、观点、案例） | 150字上下（120-180字） | 把用户原话融入文案，内容更充实 |
| 用户说"没什么要说的，就用这句话" | 100字以内 | 纯金句版，短而有力 |

### 第三步：拆解素材

从用户给的素材和对话内容里提取：
1. 产品类型（年金险/医疗险/重疾险/寿险/终身护理险/增额寿等）
2. 核心卖点或情感钩子
3. 用户表达的原话、关键词、感受（对话阶段收集到的）

如果素材里产品类型不明确，按最接近的险种处理，不追问。

### 第四步：读取口吻参考

读取 `references/voice-profiles.md`，确认三人的语言特征、思维路径和禁忌。三人差异必须明显，不能写成同一段话换三个名字。

### 第五步：大咖原版创作（3条）

按以下顺序写三条，每条标注人物名：

**刘润版**：把保险翻译成商业概念，用对比框架说清作用，冷静收尾。
**李笑来版**：先戳破一个常见错觉，用残酷现实打脸，干脆给行动建议。
**黄执中版**：从一个有画面感的场景切入，挖出最痛的点，把保险翻译成痛点的解药。

**用户原话融入原则**：
- 有用户表达内容时，必须把用户的原话或关键词自然地融入文案
- 不要把用户的话改得面目全非，尽量保留原词原句
- 用户的话和金句要融合成一段，不要生硬拼接
- 没有用户表达内容时（用户说"就用这句话"），直接用素材金句展开

原版允许保留较强的表达力度，不做合规审查。

### 第六步：命题审查（合规版前置步骤）

在写合规版之前，必须先对素材做命题审查。读取 `references/compliance-check.md`，按清单逐项检查。

审查流程：
1. **提取核心判断**：从素材和用户表达里找出最关键的那句话或那个结论
2. **逐项检查五种逻辑坑**：
   - 绝对化：有没有"一定/都/从来/任何/只要…就…"
   - 因果跳跃：A 真的能推出 B 吗？中间有没有其他条件？
   - 定义偷换：有没有把 A 概念说成 B？（保证续保≠保证理赔）
   - 以偏概全：一个案例能代表全局吗？
   - 反向推断：没发生=好？发生了=坏？
3. **确定处理方式**：
   - 命题成立 → 正常写，保留原判断
   - 案例成立但结论过度 → 缩小边界，保留案例删掉过度结论
   - 命题不成立且无素材支撑 → 换成中性表述，不编

审查结果不需要输出给用户，只作为合规版创作的内部依据。

### 第七步：大咖合规版创作（3条）

在命题审查后的基础上，用同样的三人口吻写合规版。

口吻特征与原版完全一致（刘润理性、李笑来直接、黄执中共情），但必须遵守审查后确定的边界：
- 绝对化表述 → 加上"在合同约定范围内""这类情况"等限定词
- 因果跳跃 → 只说能确定的部分，不跳结论
- 定义偷换 → 用准确术语，必要时主动区分两个概念
- 以偏概全 → 保留案例，删掉"所以都/所以这家公司"
- 反向推断 → 只陈述事实，不做反向归因

合规版同样要融入用户原话。合规版不是"阉割版"，而是"把大话缩成实话"。力度可以保留，但边界必须清楚。

### 第八步：去AI味检查

6条全部写完后，对照以下硬禁令逐条检查，命中就改：

- 不用冒号（人物直接原话除外）、不用破折号
- 不写"不是……而是……""与其说……不如说……"等翻案腔
- 不写三项以上同构排比
- 不用"说白了""说穿了""先说结论"
- 不用"值得注意的是""从某种意义上说"当洞察路标
- 不把动词名词化（"实现了保障"改成"保了什么"）
- 非虚构内容不用"浪潮""底座""钥匙"等借喻包装抽象概念
- 不喊口号、不堆形容词、不用"家人们""宝子们"

以上规则来自 human-writing skill 的成稿禁令，这里只保留与短文案相关的部分。

### 第九步：字数校验

每条正文（不含"刘润版"等标注）必须符合第二步确定的字数档位：
- 有用户表达内容：150字上下（120-180字），超出就精简，不足就补充用户表达的细节
- 用户说"就用这句话"：100字以内，超出就删

## 输出格式

分两组输出，每组三条，每条前面标注人物名。不写额外解释、不写创作思路、不附来源、不输出命题审查过程、不输出对话记录。

## 边界

- 用户要求其他大咖口吻时，先按已知特征写，不熟悉的人物如实说明，不编造风格。
- 用户要求其他字数限制时，以用户要求为准。
- 用户只给素材没说要几种版本时，默认输出6条（3原版+3合规版），这是本skill的默认交付形态。
- 用户明确说"只要原版"时，跳过第六步和第七步，只输出3条原版。
- 用户明确说"只要合规版"时，跳过第五步，直接从第六步开始，输出3条合规版。
- 用户明确说"不用问了，直接写"时，跳过第一步对话挖素材，直接进入生成，字数按100字以内处理。
- 对话阶段最多3轮，不要无限追问；用户表达了足够内容就及时收尾进入生成。
